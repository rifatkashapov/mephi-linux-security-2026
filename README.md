# mephi-linux-security-2026
ДЗ №1 Изучение средств защиты ОС GNU/Linux

## 1. Создание пользователя и настройка параметров учётной записи

В системе был создан обычный пользователь `user1` с идентификатором UID `1234`. Пользователь был добавлен в группу `students`.

Для создания группы и пользователя использовались команды:

```bash
sudo groupadd students
sudo useradd -m -u 1234 -g students user1
sudo passwd user1
```

Параметр `-m` обеспечивает создание домашнего каталога `/home/user1`, параметр `-u 1234` задаёт идентификатор пользователя, а параметр `-g students` указывает основную группу пользователя.

Для проверки параметров пользователя была выполнена команда:

```bash
id user1
```

В результате было подтверждено, что пользователь имеет UID `1234` и входит в группу `students`.

Для настройки обязательной смены пароля каждые три месяца была использована команда:

```bash
sudo chage -M 90 user1
```

Значение `90` задаёт максимальный срок действия пароля в днях.

Проверка настроек срока действия пароля была выполнена командой:

```bash
sudo chage -l user1
```

Таким образом, была создана учётная запись обычного пользователя и настроено периодическое изменение его пароля.

## 2. Мониторинг файлов и процессов

### 2.1. Поиск файлов с установленным битом set-UID

Для поиска всех обычных файлов с установленным битом `set-UID` была выполнена команда:

```bash
sudo find / -type f -perm -4000 2>/dev/null
```

Для получения дополнительной информации о правах доступа файлов использовалась команда:

```bash
sudo find / -type f -perm -4000 -exec ls -l {} \; 2>/dev/null
```

В результате были обнаружены системные программы, имеющие установленный бит `set-UID`, например программа `passwd`.

Для проверки прав программы `passwd` была выполнена команда:

```bash
ls -l /usr/bin/passwd
```

В правах доступа присутствовал символ `s`:

```text
-rwsr-xr-x
```

Это означает, что при запуске программы её эффективный UID становится равным UID владельца исполняемого файла. Так как владельцем `passwd` является `root`, программа получает необходимые повышенные привилегии.

### 2.2. Поиск процессов с повышенными привилегиями

Для отображения реального и эффективного UID процессов была использована команда:

```bash
ps -eo ruid,euid,pid,user,euser,comm,args
```

Для поиска процессов, у которых эффективный UID равен `0`, а реальный UID принадлежит обычному пользователю, использовалась фильтрация:

```bash
ps -eo ruid,euid,pid,user,euser,comm,args | \
awk 'NR==1 || ($1 >= 1000 && $1 < 65534 && $2 == 0)'
```

Так как подходящего процесса могло не быть в момент проверки, под пользователем `user1` была запущена команда смены пароля:

```bash
su - user1
passwd
```

Во втором терминале был выполнен поиск процесса `passwd`:

```bash
ps -C passwd -o pid,ruid,euid,user,euser,comm,args
```

В результате было видно, что процесс имеет реальный UID пользователя `user1`, то есть `1234`, и эффективный UID `0`.

Это подтверждает работу механизма `set-UID`: программа запускается обычным пользователем, но во время выполнения получает эффективные права владельца файла — пользователя `root`.

## 3. Изучение механизма set-UID

### 3.1. Выбор утилиты

Для исследования механизма `set-UID` была выбрана утилита:

```bash
/bin/cat
```

В качестве привилегированной операции было выбрано чтение файла, доступного только пользователю `root`.

Был создан тестовый файл:

```bash
sudo sh -c 'echo "SECRET: setuid works" > /root/setuid_test.txt'
sudo chmod 600 /root/setuid_test.txt
sudo chown root:root /root/setuid_test.txt
```

Права файла:

```text
-rw------- root root
```

При попытке прочитать файл обычным пользователем:

```bash
/bin/cat /root/setuid_test.txt
```

была получена ошибка:

```text
Permission denied
```

Таким образом, было подтверждено, что пользователь `user1` не имеет права читать данный файл.

### 3.2. Выполнение операции с использованием set-UID

Утилита `cat` была скопирована в домашнюю директорию пользователя:

```bash
sudo cp /bin/cat /home/user1/cat-suid
```

Владельцем копии был установлен `root`:

```bash
sudo chown root:root /home/user1/cat-suid
```

После этого был установлен бит `set-UID`:

```bash
sudo chmod 4755 /home/user1/cat-suid
```

Проверка прав:

```bash
ls -l /home/user1/cat-suid
```

Результат имел следующий вид:

```text
-rwsr-xr-x root root
```

Символ `s` в правах владельца показывает наличие установленного бита `set-UID`.

После этого под пользователем `user1` была выполнена команда:

```bash
/home/user1/cat-suid /root/setuid_test.txt
```

Содержимое защищённого файла было успешно прочитано:

```text
SECRET: setuid works
```

Таким образом, было подтверждено, что благодаря механизму `set-UID` программа получила эффективный UID пользователя `root` и смогла выполнить операцию, недоступную обычному пользователю.

## 4. Изучение механизма привилегий Linux Capabilities

### 4.1. Выбор утилиты

Для изучения механизма Linux Capabilities была выбрана утилита:

```bash
/bin/chown
```

В качестве привилегированной операции было выбрано изменение владельца файла на пользователя `root`.

Под пользователем `user1` был создан тестовый файл:

```bash
touch ~/test.txt
```

Попытка изменить владельца обычной утилитой:

```bash
chown root ~/test.txt
```

завершилась ошибкой:

```text
Operation not permitted
```

Это подтверждает, что обычный пользователь не имеет права произвольно изменять владельца файла.

### 4.2. Выполнение операции с помощью Linux Capabilities

Утилита `chown` была скопирована в домашнюю директорию пользователя:

```bash
sudo cp /bin/chown /home/user1/chown-cap
sudo chown root:root /home/user1/chown-cap
sudo chmod 755 /home/user1/chown-cap
```

После этого программе была предоставлена capability `CAP_CHOWN`:

```bash
sudo setcap cap_chown+ep /home/user1/chown-cap
```

Проверка установленной capability была выполнена командой:

```bash
getcap /home/user1/chown-cap
```

Результат:

```text
/home/user1/chown-cap cap_chown=ep
```

После этого под пользователем `user1` была выполнена команда:

```bash
~/chown-cap root ~/test.txt
```

Проверка:

```bash
ls -l ~/test.txt
```

показала, что владельцем файла стал пользователь `root`.

Таким образом, привилегированная операция была выполнена без использования полного набора прав суперпользователя. Программа получила только capability `CAP_CHOWN`, необходимую для изменения владельца файлов.

Данный механизм соответствует принципу минимальных привилегий: программе предоставляются только те права, которые необходимы ей для выполнения конкретной операции.

## 5. Изучение механизма sudo

В заключительной части работы пользователю `user1` было разрешено изменять системное время с использованием механизма `sudo`.

Для этого был создан отдельный конфигурационный файл:

```bash
sudo visudo -f /etc/sudoers.d/user1-time
```

В файл было добавлено правило:

```text
user1 ALL=(root) /usr/bin/timedatectl set-time *
```

Данное правило разрешает пользователю `user1` запускать команду `timedatectl set-time` от имени пользователя `root`.

После создания файла были настроены корректные права доступа:

```bash
sudo chown root:root /etc/sudoers.d/user1-time
sudo chmod 0440 /etc/sudoers.d/user1-time
```

Права `0440` необходимы для безопасного использования файлов конфигурации `sudoers`.

Корректность конфигурации была проверена командой:

```bash
sudo visudo -c
```

Система сообщила об успешном разборе конфигурационных файлов:

```text
/etc/sudoers: parsed OK
/etc/sudoers.d/user1-time: parsed OK
```

После этого под пользователем `user1` была выполнена проверка доступных команд:

```bash
sudo -l
```

В списке разрешённых команд присутствовала команда:

```text
/usr/bin/timedatectl set-time *
```

Для проверки механизма было выполнено изменение системного времени:

```bash
sudo timedatectl set-time "2026-09-15 23:30:00"
```

После выполнения команды системное время было проверено:

```bash
date
```

Изменение времени было выполнено успешно.

Если в системе была включена автоматическая синхронизация времени NTP, перед ручной установкой времени она отключалась:

```bash
sudo timedatectl set-ntp false
```

После завершения эксперимента синхронизация времени могла быть включена обратно:

```bash
sudo timedatectl set-ntp true
```

## Вывод

В ходе работы были изучены основные механизмы управления привилегиями в Linux.

Была создана учётная запись обычного пользователя с заданным UID, группой и сроком действия пароля. Были исследованы файлы с установленным битом `set-UID` и процессы, использующие разные реальные и эффективные идентификаторы пользователей.

На практике была продемонстрирована работа механизма `set-UID`, позволяющего программе получать эффективные права владельца исполняемого файла.

Также был исследован механизм Linux Capabilities, позволяющий предоставить программе отдельную привилегию без выдачи полного набора прав пользователя `root`.

В завершение был настроен механизм `sudo`, с помощью которого пользователю было предоставлено право выполнять конкретную административную операцию — изменение системного времени.

Таким образом, механизмы `set-UID`, Linux Capabilities и `sudo` позволяют различными способами предоставлять обычным пользователям или программам необходимые повышенные привилегии, при этом механизм Linux Capabilities и точечная настройка `sudo` позволяют более строго соблюдать принцип минимально необходимых прав.
